## 6. 작업·배포 방법
작업 규칙(브랜치, 버전, 배포 확인)은 `CLAUDE.md`를 따른다. 요약:
1. `main`을 pull해서 최신으로 맞추고 `feature/짧은설명` 브랜치를 딴다.
2. 브랜치에서 작업하고 push한다. 버전·README 업데이트 소식·노트 버전 항목은 건드리지 않고, 한 일은 10번 메모에 적는다.
3. 다이앤이 확인하면 `main`에 합친다. 이때 한 번만:
   - `index.html` 맨 위의 `VERSION`, `BUILD_TIME`을 다이앤이 정한 값으로 바꾼다.
   - README 「📢 업데이트 소식」 맨 위에 새 칸을 추가한다.
   - 이 노트의 버전 항목을 고치고 10번 메모를 본문에 반영한다.
4. 1~2분 뒤 사이트를 열어 버전 표시를 확인한다. GitHub API로 받은 파일의 SHA-256을 원본과 비교하면 확실하다.
- **올리는 수단:** claude.ai 채팅과 Claude Code 모두 저장소에 직접 push할 수 있다(2026-11-18 GitHub 쓰기 권한 연결). 연결이 안 되는 곳에서는 다이앤이 Add file → Upload files로 올린다.
- **로컬 미리보기 (빠른 수정용):** 저장소 폴더에서 `npx live-server --port=8000`을 켜 두면 `http://localhost:8000`에 게임이 뜨고, `index.html`이 바뀔 때마다(다이앤이 저장하든 Claude Code가 고치든) 브라우저가 자동으로 새로고침된다. 탭 두 개로 온라인 시험을 할 때는 `?local`. 이 상태에서 Claude Code에 「빠르게: …」로 시키는 방식은 `CLAUDE.md`의 「빠른 수정 모드」 참고.
- **테스트용 three.js:** 작업 환경에서 cdnjs가 막히면 `npm pack three@0.128.0`으로 받은 `build/three.min.js`를 Playwright `page.route('**/three.min.js', …)`로 바꿔 끼운다. 서버는 `python3 -m http.server`.
- **테스트(Claude 쪽):** 작업 환경에서 headless Chrome(swiftshader)과 로컬 three.js로 화면을 찍어 확인. `?local`로 탭 두 개 동기화 시험. 실제 인터넷을 거친 P2P 연결은 작업 환경에서 시험할 수 없다.

- 버전마다 README 업데이트 소식에 **다이앤의 한마디**를 인용문으로 넣는다. 한마디 **사이사이에 Claude가 이모티콘을 넣는다.**
- 제목 형식: `### v2.11 · 2026년 11월 18일 11:30 (KST)` (날짜와 시간 모두, 최신이 위로).

## 9. 주의할 점
- 노래 가사·시는 쓰지 않는다 (사랑방 대사를 새로 쓴 이유).
- 수익화를 할 경우 실존 인물 이름("박현빈 사랑방" 등)은 퍼블리시티권 문제가 생길 수 있다.
- v2.4 이하를 켜 둔 사람에게는 옥상(높이 69)에 있는 손님이 보이지 않음(예전 상태 검사가 높이 4 미만만 받음). 새로고침하면 해결.
- P2P라 한 방에 12명이 한계. 방화벽이 강한 망에서는 일부 연결이 안 될 수 있다 (TURN 서버 없음).
- 비즈니스 아이디어로 이야기한 것: 매점을 실제 후원으로, 이벤트탕 스폰서, 프라이빗 탕방 대관, 꾸미기 아이템, 목욕탕 B2B, 지원사업·연구. 아직 결정 안 함.

## 10. 브랜치 작업 메모
브랜치에서 한 일을 여기에 적는다. `main`에 합칠 때 위 본문(3~5번 등)에 반영하고 해당 메모는 지운다.
**작업을 시작하면 바로 「진행 중」으로 한 줄 적고 브랜치를 push**해서, 동시에 일하는 다른 세션이 보게 한다.

형식: `- feature/이름 (YYYY-MM-DD, 진행 중 | 확인 대기): 한 일 요약 · 주로 고치는 구역`
