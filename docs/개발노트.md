## 3. 기능 목록 (v4.1 기준)
**🆕 v4.1 (2026-11-27)**
- 📺 **전자 게시판 6대** (`DISPLAYS`, `buildDisplay`): ① 폭포탕 옆 입간판 ② 담장 너머 큰 폭포 옆 대형 전광판(기둥, 15×11.25, 바닥 7m) ③ 북쪽 울타리 ④ 동쪽 울타리 = **오송희 귤&에너지 주식회사 광고**(캔버스 그림 `osongTex`) ⑤ 서쪽 마당 작은 입간판 ⑥ 로비 동쪽 벽걸이. 광고 말고는 `BANNER_FILES`(banner1·2.jpg) 중 **화면마다 랜덤 한 장**, 대형 전광판만 **번갈아**(9초 보여주고 2초 크로스페이드, `displayFrame`). 화면은 `MeshBasicMaterial`(낮·밤 상관없이 밝음). 첫 그림 비율이 4:3과 2% 넘게 다르면 다시 짬. 정지 부품은 `mergeUnder`로 묶음 안에서 합침.
- 🏸 **배드민턴 꾸미기**: 상의 「배드민턴 유니폼」, 하의 「배드민턴 반바지」·「배드민턴 치마」, 액세서리 「배드민턴 라켓」(오른손, `makeRacket`)·「배드민턴 가방」(등에 대각선, 라켓 손잡이 둘). **액세서리 여러 개 동시 착용**: 꾸미기 배열에 `am`(비트) 칸 추가(14칸), `ac`는 예전 손님 호환용으로 첫 번째 것만(`syncAc`, `accMask`). 예전 13칸 배열도 받아줌. 키오스크 액세서리 탭은 눌러서 켜고 끄기, 「없음」은 전부 끄기.
- 🌾 **농부 이상민** 이름 복구(이름표·도움말·HUD, 「농부이」 오타도 고침) + 오른손에 배드민턴 라켓. 귤 배달 길(`FK`)은 귤 슬라이드 탑을 피해 북쪽 z -31.3 길로.
- 🪜 **지하 계단 뚫음**: 로비 대리석 바닥이 계단 구멍을 덮고 있던 것 → 구멍을 비우고 세 조각으로 깖(무늬 이어짐). 「↓ 찜질방 B1」 입간판을 통로(z 31~33)에서 계단 난간 바깥(6.6, 34.6)으로 옮김.
- 🚧 **엘리베이터 1·2층 수리 중**(`EFL`의 `broken:1`): 문 앞 노란 안내판 + 줄무늬 바리케이드(충돌), 호출 버튼 안 뜸, 안에서도 1·2 버튼 꺼짐. 지하(B1)↔옥상(R)만 운행. 처음 칸 위치는 B1.
- 🚪 **정문 유리 자동문**(`sdoors`): 사람이 2m쯤 다가오면 양쪽으로 미끄러져 열림. **탈의실 문 4개 없앰**(남탕·여탕 앞문·뒷문).
- 🍊 **귤탕 확대**(반지름 3.4→4.6, 껍질 통 `BIN`은 바깥으로) + **귤 슬라이드**(`GSL`): 귤탕 북동쪽 높이 10.4m 탑(30, -27.5)에서 반지름 3.1로 **세 바퀴** 돌아 귤탕에 풍덩(약 8초). 주황·노랑 줄무늬 관, 귤 모양 지붕, 사다리, 받침 팔. 타는 동안 `SLIDE.ride={g:1,…}`를 써서 기존 잠금·버튼 조건 그대로(`gSlideRide`). 단풍나무 하나(27,-29)를 (23,-32.4)로 옮김.
- 🍊 **귤 그냥 먹기**(`quickEatBtn`, `QE`·`qeFrame`): 미니게임 없이 집어서 2초 냠냠 먹는 시늉, 공유 상태(JZ)에는 다 먹은 것으로.
- 🌌 **밤하늘**: 하늘 셰이더에 별을 훨씬 많이(두 겹, 반짝임), 은하수 띠, 큰 보름달(무늬·달무리). 별자리 5개(`CONST`: 북두칠성·북극성·카시오페이아·오리온·백조자리)를 밝은 별로 띄우고, 밤에 바깥에서 1초 넘게 바라보면 「찾았어요!」(풍경 소리, `localStorage` `morak-stars`) → 그 뒤로는 바라볼 때 선·이름이 보임. 별똥별 4~11초마다. 바깥에선 고개를 더 들 수 있음(`pitchMin` -0.62). `sky41Frame`.
- 💡 **가로등 8개**(`SLAMP`): 밤(nightF>0.4)에만 머리가 켜지고 바닥 빛 웅덩이·후광(진짜 조명 추가 없음). 정지 부품은 합치기 대상, 머리 재질은 `userData.keep`로 따로 남겨 색만 바꿈.

**⚡ 성능 (v2.3.1)**
- 움직이지 않는 메시를 재질별로 합쳐 그리기 횟수를 절반 넘게 줄임 (탈의실 737→349, 바깥 479→182, 찜질방 927→423). scene 바로 아래의 불투명 Lambert/Basic 메시는 재질 모양과 40m 구역별로, 가만히 있는 손님 아바타는 통째로, 걷는 NPC는 팔다리를 빼고 몸통만 합침 (`mergeStatic`, `mergeUnder`). 합친 원본은 장면에서만 빠지고 카메라 충돌(`blockers`)에는 그대로 쓰임. 시간대에 따라 색이 바뀌는 `lampMat`은 따로 묶음.
- **⚠️ 앞으로 움직일 물건을 scene에 바로 넣을 때는 `mesh.userData.dyn=1`을 붙여야 합쳐지지 않는다.** (그룹 안에 넣은 물건은 해당 없음. 단, 손님 아바타와 걷는 NPC 몸통은 합쳐지므로 나중에 바꾸려면 합치기 대상에서 빼야 함.)

- 해상도 자동 조절: 휴대폰은 최대 ×1.5로 시작, 2초 평균 38fps 아래면 0.2씩 낮춤(최저 ×0.8, PC는 ×1), 57fps 이상이면 다시 올림.
- 주소 끝에 `?fps` → 화면 위에 fps·그리기 횟수·삼각형·해상도·합친 개수 표시.
- 화면 가장자리 비네트(`#vign`).
- 남은 큰 부담: 걷는 NPC와 다른 손님 아바타(사람당 10~20번), 간판처럼 텍스처가 제각각인 물체.

- 위치·방향·자세·옷·머리·색·닉네임(`n`)·꾸미기(`L`, 14칸 배열 — v4.1에서 `am` 추가)·좋다~!·귤 까는 중 상태를 주고받음. 채팅은 `chat` 액션(v4.1) (상태 크기 한도 800바이트). 예전 버전 손님은 기본 모습으로 보임. 저장되는 데이터는 없음 (모두 나가면 초기화).
- `?local`을 붙이면 같은 브라우저의 탭끼리 시험 가능 (BroadcastChannel).

## 6. 작업·배포 방법
작업 규칙(브랜치, 버전, 배포 확인)은 `CLAUDE.md`를 따른다. 요약:
1. `main`을 pull해서 최신으로 맞추고 `feature/짧은설명` 브랜치를 딴다.
2. 브랜치에서 작업하고 push한다. 버전·README 업데이트 소식·노트 버전 항목은 건드리지 않고, 한 일은 10번 메모에 적는다.
3. 다이앤이 확인하면 `main`에 합친다. 이때 한 번만:
   - `index.html` 맨 위의 `VERSION`, `BUILD_TIME`을 다이앤이 정한 값으로 바꾼다.
   - README 「📢 업데이트 소식」 맨 위에 새 칸을 추가한다.
   - 이 노트의 버전 항목을 고치고 10번 메모를 본문에 반영한다.
4. 1~2분 뒤 사이트를 열어 버전 표시를 확인한다. GitHub API로 받은 파일의 SHA-256을 원본과 비교하면 확실하다.
- **올리는 수단:** claude.ai 채팅과 Claude Code 모두 저장소에 직접 push할 수 있다(2026-11-18 GitHub 쓰기 권한 연결). 연결이 안 되는 곳에서는 다이앤이 Add file → Upload files로 올린다.
- **로컬 미리보기 (빠른 수정용):** 저장소 폴더에서 `npx live-server --port=8000`을 켜 두면 `http://localhost:8000`에 게임이 뜨고, `index.html`이 바뀔 때마다(다이앤이 저장하든 Claude Code가 고치든) 브라우저가 자동으로 새로고침된다. 탭 두 개로 온라인 시험을 할 때는 `?local`. 이 상태에서 Claude Code에 「빠르게: …」로 시키는 방식은 `CLAUDE.md`의 「빠른 수정 모드」 참고.
- **테스트용 three.js:** 작업 환경에서 cdnjs가 막히면 `npm pack three@0.128.0`으로 받은 `build/three.min.js`를 Playwright `page.route('**/three.min.js', …)`로 바꿔 끼운다. 서버는 `python3 -m http.server`.
- **테스트(Claude 쪽):** 작업 환경에서 headless Chrome(swiftshader)과 로컬 three.js로 화면을 찍어 확인. `?local`로 탭 두 개 동기화 시험. 실제 인터넷을 거친 P2P 연결은 작업 환경에서 시험할 수 없다.

## 9. 주의할 점
- 노래 가사·시는 쓰지 않는다 (사랑방 대사를 새로 쓴 이유).
- 수익화를 할 경우 실존 인물 이름("박현빈 사랑방" 등)은 퍼블리시티권 문제가 생길 수 있다.
- v2.4 이하를 켜 둔 사람에게는 옥상(높이 69)에 있는 손님이 보이지 않음(예전 상태 검사가 높이 4 미만만 받음). 새로고침하면 해결.
- P2P라 한 방에 12명이 한계. 방화벽이 강한 망에서는 일부 연결이 안 될 수 있다 (TURN 서버 없음).
- 비즈니스 아이디어로 이야기한 것: 매점을 실제 후원으로, 이벤트탕 스폰서, 프라이빗 탕방 대관, 꾸미기 아이템, 목욕탕 B2B, 지원사업·연구. 아직 결정 안 함.
